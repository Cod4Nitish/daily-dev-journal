# Day 12 · 2026-11-15 · Custom React hooks

_Category: React · Source: gemini_

Today I finally moved past the boilerplate of managing repetitive state in my components by writing my first custom hook. I realized that custom hooks aren’t magic; they are simply functions prefixed with `use` that leverage existing React primitives. The key takeaway for me was realizing that hooks share logic, not state. Every time a component calls `useToggle`, it receives its own isolated state instance, which makes the logic incredibly reusable across different parts of the UI.

I focused on returning a stable API, specifically an array containing the current value and a memoized toggle function. This keeps the consuming components clean and readable. Here is the implementation I settled on:

```javascript
function useToggle(initial = false) {
  const [value, setValue] = useState(initial);
  const toggle = useCallback(() => setValue((v) => !v), []);
  return [value, toggle];
}
```

By abstracting this stateful logic, I’ve managed to delete dozens of lines of redundant code. It is satisfying to see how much cleaner my component files look now.
