# Day 14 · 2026-11-17 · Git bisect

_Category: Git · Source: gemini_

Today I learned how to save hours of debugging by using `git bisect`. Instead of manually checking out commits to find where a regression was introduced, I can let Git perform a binary search through my history.

I started by running `git bisect start` followed by `git bisect bad` (the current state) and `git bisect good <commit-hash>` (a known working point). Git then checked out a middle commit. After verifying the bug, I marked it `git bisect bad` or `good` until the culprit was isolated.

To make this even more efficient, I used `git bisect run` with a test script. If the script exits with a non-zero status, Git treats it as a failure and continues searching.

```bash
git bisect start
git bisect bad HEAD
git bisect good v1.0.0
git bisect run npm test
```

Finding the exact commit among 1,000 changes only took about 10 steps. This is a game-changer for tracking down elusive bugs in large codebases.
