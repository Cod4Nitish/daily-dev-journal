# Day 24 · 2026-11-27 · Security basics: JWT pitfalls

_Category: Security · Source: gemini_

Today I learned that JSON Web Tokens (JWTs) are powerful but dangerous if implemented with a "set it and forget it" mentality. My biggest takeaway is the critical importance of pinning the expected algorithm during verification. Without explicitly checking `alg`, an attacker can swap a secure `RS256` signature for `none` or `HS256` to bypass authentication entirely.

I also realized that I’ve been treating JWT payloads like secure vaults, but they are merely base64-encoded strings. Storing sensitive data like PII or internal secrets is a major vulnerability since anyone can decode the token. Moving forward, I’m strictly keeping payloads minimal and strictly using short-lived access tokens paired with rotated refresh tokens to minimize the blast radius of a leak. 

```javascript
jwt.verify(token, publicKey, { algorithms: ['RS256'] });
```

Security isn't just about using a library; it's about understanding the protocol's configuration. I’ve updated our authentication middleware to enforce strict algorithm validation, ensuring we aren't vulnerable to header manipulation attacks.
