# Day 23 · 2026-11-26 · Security basics: SQL injection

_Category: Security · Source: gemini_

Today I learned that SQL injection is fundamentally a failure to treat user input as data rather than executable code. I spent the morning reviewing our legacy codebase and realized how easily a simple string-concatenated query like `SELECT * FROM users WHERE id = '` + input + `'` creates a massive security hole. An attacker could easily bypass authentication or dump the entire database by injecting malicious SQL commands.

The most practical takeaway is that parameterized queries are the industry standard for prevention because they enforce a strict separation between the query structure and the data. While our ORM handles this automatically, I now know that using raw `execute()` methods with f-strings reintroduces the exact risk we’re trying to avoid.

```python
cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))
```

I also learned that implementing the principle of least privilege for database users is a critical safety net. Even if an injection succeeds, a restricted account limits the potential blast radius.
