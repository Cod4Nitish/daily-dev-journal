# Day 8 · 2026-11-11 · LLM tool calling

_Category: AI/LLM · Source: gemini_

Today I learned that LLM tool calling is less about "magic" and more about structured contract negotiation. I previously assumed the model executed the functions directly, but it actually just returns a JSON request. My backend code acts as the ultimate gatekeeper, deciding whether to execute the tool or ignore the model’s suggestion entirely.

I discovered that the quality of my `function` definitions—specifically the `description` fields—matters significantly more than the system prompt. If I want the model to actually use a tool, I have to be brutally specific about what it does. Also, I realized that I should never return raw logs or verbose output to the LLM. Instead, I should return compact, structured JSON to keep my context window clean.

```json
{
  "name": "get_weather",
  "arguments": {"location": "San Francisco", "unit": "celsius"}
}
```

By keeping the tool output concise and the argument schemas strict, I’ve drastically reduced hallucinated parameters in my agent’s workflow.
