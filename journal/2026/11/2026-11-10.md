# Day 7 · 2026-11-10 · Prompt engineering: structured output

_Category: AI/LLM · Source: gemini_

Today I learned that "prompting for JSON" is only half the battle; the real magic lies in combining strict schema enforcement with few-shot examples. Previously, I relied on long-winded natural language instructions to describe my desired output format, but that often led to hallucinations or malformed keys. 

I’ve shifted to providing a clear JSON schema alongside two specific examples of the input-to-output transformation. This "few-shot" approach anchors the model, drastically reducing parsing failures. Most importantly, I’ve internalized that AI output is effectively untrusted input. Even with a perfect prompt, I must treat the response as potentially malicious or malformed. I’m now using a strict validation layer to ensure the structure matches my expectations before it ever touches my database.

```json
{
  "id": "string",
  "tags": ["string"],
  "confidence": "number"
}
```

Building this validation step into my pipeline has saved me from countless downstream errors and keeps my data integrity intact. It’s a simple shift, but it makes the LLM feel like a predictable API component.
