# Day 18 · 2026-11-21 · System design: idempotency keys

_Category: System Design · Source: offline_

Today I revisited **System design: idempotency keys** (System Design).

- Clients send a unique key so retried POSTs do not create duplicates.
- The server stores the key with the first response and replays it on retries.
- Keys need an expiry window, commonly 24 hours.

```python
if (saved := store.get(idem_key)):
    return saved
resp = create_payment(body)
store.set(idem_key, resp, ttl=86400)
return resp
```

Takeaway: Clients send a unique key so retried POSTs do not create duplicates.
