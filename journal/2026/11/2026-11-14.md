# Day 11 · 2026-11-14 · React useMemo vs useCallback

_Category: React · Source: gemini_

Today I finally demystified the performance trade-offs between `useMemo` and `useCallback`. I used to think wrapping everything in these hooks was a "best practice," but I realized that premature memoization actually introduces overhead due to memory allocation and shallow comparison checks.

The core distinction is simple: `useMemo` caches the result of an expensive calculation, while `useCallback` caches the function instance itself. Both are only truly useful when you pass these values as props to a component wrapped in `React.memo` or include them in a `useEffect` dependency array. If the child component isn't memoized, the reference stability is effectively wasted.

```javascript
const memoizedValue = useMemo(() => computeExpensiveValue(a, b), [a, b]);
const memoizedCallback = useCallback(() => doSomething(a), [a]);
```

I’m learning to stop guessing and start profiling. Before reaching for these hooks, I’ll use the React DevTools Profiler to identify actual bottlenecks. If the component isn't re-rendering unnecessarily, the cost of memoization isn't worth the complexity.
