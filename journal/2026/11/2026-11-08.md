# Day 5 · 2026-11-08 · Hybrid search for RAG

_Category: AI/RAG · Source: gemini_

Today I learned that relying solely on dense embeddings for RAG is a mistake when dealing with technical documentation. While embeddings excel at capturing semantic intent, they often struggle with specific identifiers like obscure error codes or unique product names. 

I implemented a hybrid search strategy to bridge this gap. By combining a vector store with a BM25 index, I can capture both conceptual similarity and exact keyword matches. To merge these results, I used Reciprocal Rank Fusion (RRF). It’s elegant because it normalizes the rankings without needing to manually tune weights between disparately scaled scores. Finally, passing the top 40 candidates through a cross-encoder reranker provided a massive boost in precision, far exceeding what I achieved by just tweaking embedding parameters.

```python
combined_scores = {}
for rank, doc in enumerate(list_a + list_b):
    combined_scores[doc] += 1 / (k + rank)
```

The performance gain is undeniable; my retrieval accuracy for technical queries feels significantly more robust.
