# Day 2 · 2026-11-05 · FastAPI background tasks

_Category: FastAPI · Source: gemini_

Today I learned how to offload non-critical operations in FastAPI using the `BackgroundTasks` utility. It is surprisingly simple: you inject the `BackgroundTasks` object into your path operation, and then use the `.add_task()` method to queue functions that should execute after the response has been sent to the client.

```python
from fastapi import BackgroundTasks

@app.post("/notify/{email}")
async def notify(email: str, background_tasks: BackgroundTasks):
    background_tasks.add_task(send_email, email)
    return {"message": "Notification queued"}
```

I realized that this runs in the same process, so it is perfect for lightweight tasks like sending a confirmation email or clearing a small cache. However, it is not a replacement for a robust task queue like Celery; if the process crashes, the task is lost. Also, since the response is sent before the task finishes, any exceptions raised inside the background function won't affect the HTTP status code returned to the user. Use it for fire-and-forget logic only.
