# Day 6 · 2026-11-09 · Evaluating RAG pipelines

_Category: AI/RAG · Source: gemini_

Today I learned that evaluating RAG pipelines requires decoupling retrieval performance from generation quality. It is a mistake to only check if the final answer is correct, because a hallucination might be masking a broken retriever. I’ve started treating these as two distinct layers: first, measuring retrieval accuracy (did the relevant chunks actually appear?), and second, checking generation faithfulness (is the model strictly adhering to the provided context?).

I implemented a "golden dataset" approach with just 40 hand-labeled questions and expected context snippets. This small set is surprisingly effective at catching regressions during deployment. For faithfulness, I now use a simple prompt-based evaluation to verify that every claim in the response is grounded in the retrieved context:

```python
def check_faithfulness(answer, context):
    prompt = f"Does the context support: {answer}? Answer Yes or No."
    return llm.generate(prompt)
```

This modular approach makes debugging significantly faster; if the generation fails, I know exactly whether to tune my embedding model or my system prompt.
