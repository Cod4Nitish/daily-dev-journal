# Day 3 · 2026-11-06 · Pydantic v2 validators

_Category: Python · Source: gemini_

Today I dove into Pydantic v2 and finally replaced my clunky v1 `validator` methods. The new `field_validator` is much cleaner; it’s now a standard `@classmethod` that explicitly handles validation logic for specific fields.

For cross-field dependencies, I switched to `model_validator(mode="after")`. This is a game-changer because it allows me to inspect the fully instantiated model, making it trivial to ensure, for example, that an `end_date` is strictly after a `start_date`.

```python
from pydantic import BaseModel, model_validator

class Event(BaseModel):
    start: int
    end: int

    @model_validator(mode="after")
    def check_order(self):
        if self.end <= self.start:
            raise ValueError("End must be after start")
        return self
```

I also refined my API update pattern. By using `model_dump(exclude_unset=True)`, I can now cleanly generate dictionaries for PATCH requests without accidentally overwriting fields the user didn't provide. Pydantic v2 feels significantly more robust and intuitive for production-grade data modeling.
