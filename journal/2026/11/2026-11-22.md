# Day 19 · 2026-11-22 · Jetpack Compose state hoisting

_Category: Android · Source: gemini_

Today I learned that mastering state hoisting is the single most important step toward writing maintainable Jetpack Compose UIs. By "hoisting" state to a parent composable, I can transform a complex, unpredictable component into a stateless, reusable one. This pattern makes my UI logic significantly easier to test and preview in isolation.

The core principle is simple: pass the state value down and trigger events back up through callbacks. I’ve started following the `(value: T, onValueChange: (T) -> Unit)` pattern religiously. For instance, using `rememberSaveable` in the parent ensures that the data survives configuration changes like screen rotations, while the child remains purely a visual representation of that state.

```kotlin
@Composable
fun NameInput(name: String, onNameChange: (String) -> Unit) {
    TextField(value = name, onValueChange = onNameChange)
}
```

This approach decouples my business logic from the UI. Now, instead of debugging buried state variables, I can verify state flow by simply checking the parameters passed into my composables. It’s a cleaner, more robust architecture.
