# Day 10 · 2026-11-13 · React useEffect cleanup

_Category: React · Source: gemini_

Today I learned that `useEffect` cleanup isn't just for unmounting—it’s a vital mechanism for synchronizing state with side effects. I previously ignored the return function, but I realized that without it, your app is prone to memory leaks and race conditions. 

In React 18, `StrictMode` purposefully triggers effects twice in development. This caught me off guard, but it’s actually a brilliant way to expose missing cleanup logic. When fetching data, I learned to use `AbortController` to prevent stale updates if the component unmounts or the effect re-runs before the request finishes.

```javascript
useEffect(() => {
  const controller = new AbortController();
  fetch(url, { signal: controller.signal });
  return () => controller.abort();
}, [url]);
```

By returning a function that cancels the ongoing request, I ensure that my state updates only when the result is still relevant. It’s a small pattern, but it makes my components significantly more robust and prevents those pesky "cannot update state on an unmounted component" warnings.
