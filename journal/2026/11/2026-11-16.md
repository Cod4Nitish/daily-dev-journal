# Day 13 · 2026-11-16 · Git interactive staging

_Category: Git · Source: gemini_

Today I learned how to keep my commit history clean using Git's interactive staging. Instead of blindly running `git add .`, I’ve started using `git add -p`. This allows me to review changes hunk-by-hunk, ensuring each commit contains exactly one logical idea rather than a messy mix of unrelated changes.

When I inevitably make a mistake or realize I forgot a small tweak, I use `git commit --fixup <sha>` to create a targeted fix, followed by `git rebase -i --autosquash` to fold it into the original commit automatically. It feels like magic for maintaining a clean, readable project history. I also practiced using `git restore --staged <file>` to unstage accidental additions without wiping out the actual work in my files.

```bash
git add -p
git commit --fixup <commit-hash>
git rebase -i --autosquash main
```

These commands have fundamentally shifted how I approach version control; my pull requests are now much easier for my team to review.
